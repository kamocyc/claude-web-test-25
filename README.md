# リバーフォーク（Riverfolk）

Timberborn 風のコロニーシミュレーション。ただしビーバーではなく **人間** の入植地を育てる。
川をせき止めて貯水池を作り、乾季を越えて集落を存続させるのが目的。

TypeScript + Vite + Three.js のみで動く、ブラウザ完結のゲーム。

```bash
npm install
npm run dev      # http://localhost:5173
npm test         # シミュレーションのテスト（Vitest）
npm run build    # 型チェック + 本番ビルド
```

**サンプル** ボタンを押すと、川をせき止めて貯水池を作り、水を汲み、木を挽き、湿った土で
麦を育ててパンを焼く——という一巡が回っている町を読み込める。何から手を付けるか迷ったら
これを見るとよい（今の町は捨てられるので確認が入る）。

### 最初の数日にやること

1. **揚水ポンプ**を川岸に建てる。水は住民の生命線で、パン作りにも要る。
2. **住居**を建てて寝床を増やす（人口が増える条件でもある）。
3. **伐採小屋 → 製材所**で丸太と板材を確保する。
4. 川沿いの湿った土（濃い緑）に**農地**を置き、**パン屋**で小麦をパンにする。
5. 乾季が来る前に川へ**ダム**や**水門**を架けて貯水する。
6. 水辺から離れた畑には**灌漑塔**を建てて湿り気を届ける。

乾季になると水源が止まり、貯水池の水だけで暮らすことになる。乾いた土では作物も木も
枯れるので、水位の管理が生死を分ける。乾季はサイクルごとに 1 日ずつ長くなる。

## 水のしくみ

このゲームの中心は水のシミュレーションで、Timberborn と同じく「列（マス）ごとに
1 本の水柱を持つ」モデルを、**バーチャルパイプ法**（Mei et al. の浅水近似）で解いている。

```
bed  = 地面の高さ + 堰の高さ        … 水の底面
h    = bed + 水深                   … 水面
Q    = Q * 減衰 + dt * g * A * Δh / l * (1 - 通水抵抗)
A    = max(0, 上流側の水面 - 高い方の bed)   … パイプの濡れ断面
```

隣接する列の間の流量 Q を状態として保持するので、流れの慣性が残り、川は流れ続け、
水門を開ければ勢いよく放流され、貯水池は波打ってから水平に落ち着く。

* **A（濡れ断面）を式に挟むのが肝**。これは「堰を越える水の厚み」そのものなので、
  天端ぎりぎりではほとんど流れず、頭が付くほど勢いよく流れる。滝も同じ式で落ちる。
* **堤防・ダム・水門はすべて bed を上げるだけ**で表現される。越流も貯水も逆流防止も
  同じソルバから自然に出るので、構造物ごとの特別扱いが要らない。
  * 堤防 … 地形そのものを 1 段上げる（積み上げ可）
  * ダム … 堰高 1 で固定。超えた分だけ越流する
  * 水門 … 堰高を 0〜3 に変更できる。乾季前の水位管理の主役
  * 掘削 … 地形を 1 段下げて水路を通す
* 各列から出る流量は保有水量を超えないよう一律に縮小するので、**負の水深は生じず、
  閉じた地形では総水量が厳密に保存される**（テストで確認している）。
* 1 tick（0.1 秒）を 4 サブステップに分けて解く。ゲーム速度を変えても dt は変えないので、
  10x でも水の挙動は同じ。

### 灌漑

水辺と稼働中の灌漑塔を始点に、整数コストのダイクストラで湿り気の届く範囲を求める。
水平移動のコストは 1、1 段登るごとに +2 なので、高台は水辺のすぐ横でも乾いたままになる。
土壌水分は目標値へ徐々に動き、**乾くのは湿るより遅い**ので、乾季に入ってから灌漑塔を
建てても間に合う余地がある。

## 構成

シミュレーションと描画は完全に分かれていて、`src/sim/` は Three.js に依存しない。
乱数はシード付きのものだけを使うため、**同じシードなら完全に同じ経過をたどり、
セーブして読み込んでも以降の進行が一致する**。

```
src/
  core/    grid（列ベースのボクセル格子）, world（状態）, game（sim 一式）, rng
  sim/     water（水流ソルバ）, irrigation, season, structures（堰・掘削）,
           pathfinding（A*）, citizens, production, step（1 tick の実行順）
  data/    constants（物理・バランス定数）, buildings（建物カタログ）, mapgen, sampleTown
  render/  scene（見下ろしカメラ）, terrainMesh（チャンク分割）, waterMesh（流速シェーダ）,
           entityMesh（InstancedMesh）, ghost
  ui/      hud, buildMenu, inspector, style.css
  save/    save（JSON 直列化・localStorage）
tests/     水流・灌漑・経路探索・ワールド・経済・シナリオ・カメラ・サンプルのテスト
```

## テストで担保していること

* 閉じた地形で総水量が保存され、負の水深や NaN が出ない
* 凹地に注いだ水が水平な水面に収束する
* ダムが天端まで貯水し、超えた分だけ越流する／水門を開けると放流される
* 下流の河床が高ければ遡上しない／排水口からは抜け、崖からは抜けない
* 水中に堤防を建てても総水量が保存される
* 湿り気が距離と勾配で減衰し、灌漑塔が範囲を広げる
* 段差 2 以上は登れず、テラスにすれば登れる／深い水は通れない
* 揚水 → 伐採 → 製材 → 農業 → 製パンがつながり、人口が維持できる
* **灌漑塔を建てると耕作できる土地が広がり**、水を切らすと元の広さに戻る。
  乾いた土地に建てた農地は、灌漑が届いてはじめて実る
* **ダムで貯めた水があれば長い渇水を越えられ**、ダムが無いと川は流れ去って取水できなくなる
  （同じ地形・同じポンプ位置で、堰の有無だけを変えた比較）
* **水門を閉じておけば貯水が保たれ**、全開にすると溜めた水が下流へ流れ去る
* 同じシードで完全に同じ結果になる／セーブ・ロードを跨いでも一致する
* カメラをどの向きに回しても、W は画面奥・D は画面右へ動く
  （期待値はカメラ位置から求めた視線基底と突き合わせている）
* サンプルの町は主要な建物が揃って完成しており、働き手が付いて水と食料が増え続ける
